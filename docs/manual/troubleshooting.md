# トラブルシューティング / Troubleshooting

このドキュメントでは、PLATEAU GIS Converterの使用中に発生する可能性のある問題と、その解決方法について説明します。

## CityGMLから3D Tilesへの変換時のエラー

### エラーメッセージ: "ConversionFailed: Pipeline thread panicked"

#### 症状

CityGMLから3D Tilesへの変換時に、以下のようなエラーメッセージが表示される：

```
ConversionFailed: Pipeline thread panicked: Sink thread panicked with message: a scoped thread panicked.
```

#### 原因

このエラーは、変換処理のパイプライン内でスレッドがパニック（予期しない異常終了）した場合に発生します。主な原因は以下の通りです：

1. **メモリ不足**
   - 大規模なデータセットを処理する際にシステムメモリが不足した
   - 処理中のデータが利用可能なRAMを超えた

2. **ディスク容量不足**
   - 出力先のディスクの空き容量が不足している
   - 一時ファイルを保存するための空き容量が不足している

3. **ファイルI/Oエラー**
   - 出力先ディレクトリへの書き込み権限がない
   - ファイルシステムのエラー
   - ネットワークドライブの接続切断（ネットワーク上のディスクへ出力している場合）

4. **データの問題**
   - 破損したCityGMLファイル
   - 無効なジオメトリデータ
   - サポートされていないCityGML形式やバージョン

5. **システムリソースの競合**
   - 他のプロセスとのリソース競合
   - スレッドプールのデッドロック

#### 解決方法

##### 1. メモリの確認と対処

システムのメモリ使用状況を確認してください：

- **Windows**: タスクマネージャーでメモリ使用率を確認
- **macOS**: アクティビティモニタでメモリ使用状況を確認

**対処方法**：
- 他のアプリケーションを閉じて、利用可能なメモリを増やす
- 変換するデータを小分けにして処理する（複数のファイルに分割する）
- システムのRAMを増設する

##### 2. ディスク容量の確認

出力先のディスク容量を確認してください：

- 変換元データと同等以上の空き容量が必要です
- 安全のため、変換元データの2倍以上の空き容量を確保することを推奨します

**対処方法**：
- 不要なファイルを削除してディスク容量を確保する
- 別のドライブに出力先を変更する

##### 3. ファイルアクセス権限の確認

出力先ディレクトリへの書き込み権限があることを確認してください：

**Windows**:
- 出力先フォルダを右クリック → プロパティ → セキュリティタブで権限を確認

**macOS**:
- 出力先フォルダを選択 → 情報を見る（⌘I）→ 共有とアクセス権で権限を確認

**対処方法**：
- ユーザーディレクトリ内に出力先を設定する
- 管理者権限でアプリケーションを実行する（推奨されません）
- 書き込み権限のある別のディレクトリに出力先を変更する

##### 4. 入力データの検証

CityGMLファイルの整合性を確認してください：

- ファイルが正しくダウンロードされているか確認
- XMLとして正しく構造化されているか確認
- PLATEAU標準仕様に準拠しているか確認

**対処方法**：
- データを再ダウンロードする
- 別のCityGMLファイルで試してみる
- より小さなサンプルファイルで動作確認する

##### 5. 変換設定の調整

以下の設定を調整してみてください：

**3D Tilesの場合**：
- テクスチャ解像度の制限を有効にする（`limit_texture_resolution`）
- より高いズームレベルから開始する（データ量を減らす）
- gzip圧縮を無効にする（処理負荷を減らす）

**コマンドライン版を使用している場合**：
```bash
# デバッグモードで実行して詳細なログを確認
RUST_BACKTRACE=1 nusamai input.gml --sink 3dtiles --output output/
```

##### 6. ログの確認

エラーの詳細情報を確認するため、以下の手順でログを取得してください：

**GUIアプリケーション**:
- アプリケーションのログ出力を確認
- エラーメッセージの前後のログを確認

**コマンドライン版**:
```bash
# 環境変数を設定してバックトレースを有効化
RUST_BACKTRACE=full nusamai input.gml --sink 3dtiles --output output/ 2>&1 | tee conversion.log
```

#### さらに詳しい診断方法

上記の対処方法で解決しない場合、以下の手順で問題を切り分けてください：

1. **最小データセットでのテスト**
   - 1つの小さなCityGMLファイルのみで変換を試す
   - 成功する場合、データ量の問題である可能性が高い

2. **他の出力形式でのテスト**
   - GeoJSONやGeoPackageなど、他の形式への変換を試す
   - 他の形式で成功する場合、3D Tiles固有の問題である可能性が高い

3. **段階的なファイル追加**
   - 最初は1ファイルから始めて、徐々にファイル数を増やす
   - エラーが発生するポイントを特定する

4. **システムリソースの監視**
   - 変換中のCPU、メモリ、ディスクI/Oを監視する
   - ボトルネックとなっているリソースを特定する

#### 問題が解決しない場合

上記の対処方法でも問題が解決しない場合は、以下の情報を含めてGitHubのIssueで報告してください：

- 使用しているOSとバージョン
- PLATEAU GIS Converterのバージョン
- 入力CityGMLファイルの情報（ファイルサイズ、地域、データタイプ）
- エラーメッセージの全文
- 実行時のログ（`RUST_BACKTRACE=1`を設定した状態で取得）
- システムのメモリとディスク容量の情報

## その他のエラー

### 変換が途中で停止する

#### 原因
- ネットワークドライブへの出力時の接続切断
- スリープモードへの移行
- 非常に大きなデータセットの処理

#### 対処方法
- ローカルドライブに出力する
- 電源設定でスリープを無効にする
- データを分割して処理する

### 出力ファイルが開けない

#### 原因
- 不完全な変換（途中終了）
- 対応していないビューアーの使用

#### 対処方法
- 変換を最後まで完了させる
- 適切なビューアーを使用する（3D Tilesの場合はCesiumなど）

## パフォーマンスの最適化

### 変換速度を向上させるには

1. **CPUコア数の多いマシンを使用**
   - 変換処理は並列化されているため、多コアCPUで高速化します

2. **SSDを使用**
   - HDDよりもSSDの方が、I/O性能が高く高速に処理できます

3. **十分なメモリを確保**
   - 推奨メモリ容量：処理するデータサイズの3〜5倍

4. **不要なアプリケーションを終了**
   - システムリソースを変換処理に集中させます
